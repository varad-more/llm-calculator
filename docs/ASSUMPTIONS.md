# Assumptions

Every empirical constant the model uses. Nothing is hardcoded in the math; each value below is
an entry in [`data/assumptions.json`](../data/assumptions.json) and is overridable at every
layer:

```bash
llmsize plan ... --assume mbu_decode=0.72 --assume cuda_context_bytes=805306368
```

```ts
size({ ..., assume: { mbu_decode: 0.72 } })
```

Confidence is honest. **low** means we could not find a primary source and the value is a
community-reported ballpark — if a prediction hinges on a low-confidence constant, that is
where to point your scepticism, and a validation log is worth more than an argument.

### `driver_reserved_vram_fraction`

**0.004** (fraction) · confidence: **medium**

nvidia-smi reports slightly less total memory than the nominal capacity (ECC/driver/page tables). e.g. an 80GB H100 reports ~81559 MiB of 81920 MiB nominal (0.44%).

Source: <https://forums.developer.nvidia.com/t/why-does-nvidia-smi-report-less-memory-than-the-gpu-has/64165>

### `cuda_context_bytes`

**536870912** bytes · confidence: **low**

CUDA context + cuBLAS/cuDNN workspaces + NVML per process, before any model load. vLLM reports this as part of 'non-torch memory'; commonly 0.3-0.9 GiB depending on driver and CUDA version.

Source: <https://github.com/vllm-project/vllm/blob/main/vllm/worker/worker.py>

### `nccl_buffer_bytes_per_rank`

**536870912** bytes · confidence: **low**

NCCL communicator buffers + CUDA IPC handles per rank when TP>1. Driven by NCCL_BUFFSIZE (default 4MiB per channel) times channels, plus graph-captured comm buffers. 0.5 GiB is the commonly observed delta between TP=1 and TP=2 non-torch memory.

Source: <https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/env.html>

### `cudagraph_base_bytes`

**268435456** bytes · confidence: **low**

Fixed cost of CUDA graph capture pools in vLLM when enforce_eager=False.

Source: <https://docs.vllm.ai/en/latest/configuration/optimization.html>

### `cudagraph_bytes_per_captured_size`

**8388608** bytes · confidence: **low**

Per captured batch size, vLLM holds graph node structures and static input/output buffers. vLLM's default capture list has ~35 sizes and total graph memory is typically 1-3 GiB.

Source: <https://github.com/vllm-project/vllm/blob/main/vllm/config/compilation.py>

### `prefill_activation_multiplier`

**4** count · confidence: **medium**

Number of live hidden-size-shaped activation buffers during a prefill chunk (residual stream, qkv projection output, attention output, plus one transient). Flash-attention avoids materialising the S x S score matrix, so the quadratic term is excluded.

Source: <https://arxiv.org/abs/2205.14135>

### `allocator_fragmentation_fraction`

**0.02** (fraction) · confidence: **low**

PyTorch caching allocator holds reserved-but-unallocated blocks. vLLM's profiling run measures peak reserved, not peak allocated, so a small slack remains.

Source: <https://pytorch.org/docs/stable/notes/cuda.html#memory-management>

### `mbu_decode`

**0.65** (fraction) · confidence: **medium**

Model Bandwidth Utilisation achieved by a well-tuned decode kernel on a modern engine. Databricks measured 0.55-0.72 across model sizes on A100/H100.

Source: <https://www.databricks.com/blog/llm-inference-performance-engineering-best-practices>

### `mfu_prefill`

**0.45** (fraction) · confidence: **medium**

Model FLOPs Utilisation for compute-bound prefill. PaLM reported 0.46 MFU for training; large-batch prefill lands in a similar band, lower for small hidden sizes.

Source: <https://arxiv.org/abs/2204.02311>

### `quant_group_size`

**128** count · confidence: **high**

Default group size for GPTQ/AWQ int4 packing. Each group carries a scale (and a zero point for asymmetric schemes).

Source: <https://arxiv.org/abs/2306.00978>

### `interconnect_efficiency`

**0.7** (fraction) · confidence: **low**

Fraction of peak NVLink/PCIe bandwidth achieved by NCCL all-reduce at the message sizes typical of TP (a few MiB).

Source: <https://github.com/NVIDIA/nccl-tests>
